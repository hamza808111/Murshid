# Murshid Cypress E2E Test Plan (Sunny + Rainy)

## Assumptions & Test Data

- Base URL is already set correctly in `Murshid-tests/cypress/cypress.config.js`.
- Test accounts (in your Supabase test project):
  - Admin: `admin1@admin.admin` / `adminADMIN` with `profiles.is_admin = true`.
  - User: `ayman@ayman.com` / `Ayman123`.
  - Existing email (duplicate signup check): `m.ay.albilaly@gmail.com`.
- Signup behavior: after successful signup, the app redirects directly to `/` (auto-confirm enabled).
- Use `cy.intercept()` only for rainy/negative paths (auth/profiles/ping) when needed.

## Selector Strategy

- Inputs by `id`: `#email`, `#password`, `#confirm-password` (signup), `#confirmPassword` (reset), `#name`, `#establishment_name`.
- Buttons by visible text, e.g., `cy.contains('button','Login')`.
- Shadcn Selects: locate by label text → trigger (`[role="combobox"]`) → option by visible text.
- Avoid class selectors; prefer text and ids.

## 1) Login

### Sunny

- Valid user credentials → redirect to `/`.
- Valid admin credentials → redirect to `/admin`.
- Guest login ("Continue as Guest") → redirect to `/` and show authenticated navbar.

Algorithm (user):

```js
cy.visit('/login')
cy.get('#email').type('user@test.com')
cy.get('#password').type('UserPass123!')
cy.contains('button','Login').click()
cy.url().should('match', /\/$/)
```

### Rainy

- Invalid email format → validation toast.
- Short/empty password → validation toast.
- Wrong credentials → error toast.
- Network/auth 500 → error toast (via intercept on supabase auth endpoint).

## 2) Create an Account (Signup)

### Sunny (two branches depending on Supabase email confirmation)

- Immediate session (auto-confirm on) → profile upsert → redirect `/` with success toast.
- Email confirmation required (auto-confirm off) → success toast → redirect `/login`.
- Fill optional fields and role-dependent branches (Student → High School Level or University Track; Specialist → Level).

Algorithm (immediate session):

```js
cy.visit('/signup')
cy.get('#name').type('Test User')
cy.get('#email').type('newuser@test.com')
cy.get('#password').type('Password123!')
cy.get('#confirm-password').type('Password123!')
cy.contains('button','Sign Up').click()
cy.url().should('match', /\/$/)
```

### Rainy

- Duplicate email → toast: account exists.
- Invalid email / weak password / mismatched confirm → Zod validation toasts.
- Network/profile upsert failure → warning/error toast; still allow signup completion.

## 3) Access Dashboard for Admin (`/admin`)

### Sunny

- Admin user logs in → visiting `/admin` displays dashboard sections (header, stats, users table), allows Refresh, Logout.

Algorithm:

```js
// login as admin → visit('/admin')
cy.contains('h1','Admin Dashboard')
cy.contains('button','Refresh')
cy.get('table').should('be.visible')
```

### Rainy

- Non-admin user/guest → toast "Access denied" then redirect to `/`.
- Fetch users error (500) → error toast.

## 4) Manage Users for Admin

### Sunny

- Admin can search users (filters table rows).
- Open delete dialog for a user → confirm delete → row removed → success toast.
- Cancel delete leaves table unchanged.

Algorithm (delete):

```js
// assume on /admin with table loaded
cy.get('table tbody tr').first().within(() => {
  cy.contains('button','Delete').click() // or ghost button with Trash icon
})
cy.contains('button','Delete').click() // dialog confirm
// assert row count decreased or toast success
```

### Rainy

- Attempt to delete self → toast error, button disabled.
- Admin API fails → fallback delete from `profiles` or show error toast.
- Network 500 on delete → error toast.

## 5) Edit Profile (`/profile`)

### Sunny

- Logged-in user: click "Edit Profile" → modify `#name`, `#email`, optional fields → "Save Changes" → success toast → view mode reflects updates.
- Role-dependent UI: choose Role=Student → Student Type appears; for High School → Level list; for University → Track list. Role=Specialist → Level list.

Algorithm:

```js
cy.visit('/profile')
cy.contains('button','Edit Profile').click()
cy.get('#name').clear().type('Updated Name')
cy.contains('button','Save Changes').click()
cy.contains('Updated Name')
```

### Rainy

- Invalid name/email → Zod toast error, no save.
- RLS/permission error on upsert → error toast from `updateProfile`.
- Cancel resets changes and exits edit mode.

## 6) View Profile

### Sunny

- Logged-in user sees personal and academic info sections populated with user data and conditional badges/sections (role, gender, institution, track, etc.).
- Guest user (id='guest') can access (ProtectedRoute allows any truthy user), with fields possibly "Not set".

Algorithm:

```js
cy.visit('/profile')
cy.contains('Personal Information')
cy.contains('Email Address')
```

### Rainy

- Not authenticated (no user) → ProtectedRoute redirects to `/login`.

## 7) Logout

### Sunny

- From navbar: click "Logout" → shows "Logging out..." → redirect to `/login` with success toast.

Algorithm:

```js
cy.contains('button','Logout').click()
cy.url().should('include','/login')
```

### Rainy

- Sign-out error path (simulate) → toast "Logout failed" (handled in Navbar catch) and button re-enabled.

## 8) Reset Password (Forgot + Reset)

### Sunny

- Forgot Password: enter valid email → "Password reset link sent" message; can try different email.
- Reset Password with valid session: enter strong matching passwords → success toast → auto sign-out → redirect to `/login`.

Algorithm:

```js
cy.visit('/forgot-password')
cy.get('#email').type('user@test.com')
cy.contains('button','Send Reset Link').click()
cy.contains('Password reset link sent')

// With valid reset session
cy.visit('/reset-password')
cy.get('#password').type('NewPass123!')
cy.get('#confirmPassword').type('NewPass123!')
cy.contains('button','Update Password').click()
cy.url().should('include','/login')
```

### Rainy

- Invalid email → validation toast.
- Reset: password too weak or mismatch → validation/mismatch toasts.
- No/invalid session token → error toast then redirect to `/forgot-password`.

## Negative Path Stubs (Interceptions)

- Auth error: `cy.intercept('POST','**/token?grant_type=password', {statusCode:401})` or intercept Supabase JS calls domain-specific endpoints used by the client.
- Profile upsert fail: intercept `POST/PATCH` `**/rest/v1/profiles*` → 500.
- Admin list fail: intercept `GET **/rest/v1/profiles*` → 500.
- Ping fail: intercept `GET /api/ping` → 500.
